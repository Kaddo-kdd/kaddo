# Proposal: Adapter Discovery and Status (VS-070)

## Why

After five adapters, install works but discovery still relies on the user remembering target names
and files. Several adapters share `AGENTS.md`, so it's easy to be unsure what's installed, whether a
file is team-owned / injected / fully generated / broken, and whether to use `--force` or `--inject`.

## What

Add two read-only commands:

- `kaddo adapters list` (alias `ls`) — the supported adapter catalog (id, label, target file, inject
  support). Static; needs no project. `--json` available.
- `kaddo adapters status` (alias `check`) — inspect each adapter's target file in the current project
  and report a state: `missing`, `team-owned`, `injected`, `legacy-injected`, `full-generated`,
  `broken-markers`, plus a recommended action. Detects the `origin_adapter` from the generated-by
  header and, for files shared by several adapters (`AGENTS.md`), shows `full-generated by <origin>`
  and groups them under `shared_files` in `--json`.

Both are strictly read-only: no writes, no marker migration, no git, no LLM, no `knowledge/` or
`.kaddo/` changes. They reuse the shared adapter catalog and `detectAgentsState` (refined into the
VS-070 states, distinguishing legacy markers).

## Scope

Discovery/status only. No new install behavior. The adapter catalog is centralized in the core so the
install command, list and status all share one source of truth.

## Impact

- `core/codex-adapter.ts`: `ADAPTERS` catalog, `findAdapter`, `classifyAdapterState`,
  `parseOriginAdapter`, `buildAdapterStatuses`, `buildSharedFileStatuses`.
- `commands/adapters.ts`: install now derives from `ADAPTERS`; new `runAdaptersList` / `runAdaptersStatus`.
- `index.ts`: register `adapters list` (ls) and `adapters status` (check).
- Docs EN/ES (Custom Adapters: discovery/status + states + shared AGENTS.md) + README. Minor bump 3.32.0.
