# Proposal: Reframe Token Efficiency as Context Efficiency (VS-043)

## Why

The current "Token efficiency" narrative can be misread as prompt compression, token
optimization or context-window tuning. Kaddo does none of those things.

Kaddo reduces unnecessary repository exploration by turning project knowledge into structured
context. Lower token consumption is a consequence, not the product's main promise.

## What

- Reframe the article from **Token efficiency** to **Context efficiency**.
- Introduce **Repository Exploration Tax** as the repeated discovery cost paid by agents.
- Connect context efficiency to Kaddo's Business → Product → Tech → Delivery knowledge layers.
- Keep token measurements as secondary evidence of bounded context.
- Align README, homepage, manifesto, visual guide and use-case docs in EN/ES.

## Out of scope

- CLI changes.
- Context-pack or explain behavior changes.
- Real token metrics beyond the existing illustrative table.
- Automated benchmarks.
