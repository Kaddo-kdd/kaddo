# Design: Context Efficiency Positioning

## Message hierarchy

```
Knowledge
↓
Context
↓
Less Exploration
↓
Better Decisions
↓
Token Savings (side effect)
```

Primary value proposition:

> Kaddo reduces repository exploration by turning project knowledge into structured context.
> Token savings are a consequence, not the goal.

## Article structure

The former token-efficiency article becomes a context-efficiency article:

1. The Real Cost of Exploration.
2. Repository Exploration Tax.
3. Knowledge Layers.
4. Why Token Savings Happen.
5. Measured Output Size.
6. Context Efficiency Loop.

The page explicitly states that Kaddo does not compress prompts, summarize automatically, remove
tokens or optimize context windows dynamically.
