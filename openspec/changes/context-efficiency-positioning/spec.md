# Spec: Reframe Token Efficiency as Context Efficiency

## Acceptance criteria

- **AC1** The article clearly states that Kaddo does not directly optimize tokens.
- **AC2** The concept **Repository Exploration Tax** is introduced.
- **AC3** The article connects context efficiency to Business, Product, Tech and Delivery.
- **AC4** Comparative diagrams show exploration vs structured knowledge.
- **AC5** README is updated.
- **AC6** Manifesto is updated.
- **AC7** Visual Guide is updated.
- **AC8** EN/ES parity is maintained.
- **AC9** The main value proposition shifts from "Token Efficiency" to "Context Efficiency
  through Structured Knowledge" while keeping token savings as a secondary benefit.

## Non-goals

- No CLI behavior changes.
- No context-pack or explain changes.
- No new token metrics or automated benchmarks.
