# Proposal: Agent and Skill Version Metadata (VS-074.2)

## Why

The CLI version doesn't guarantee the version of the agents/skills installed in a project. An updated
package can sit next to agents/skills generated by an older release, producing inconsistent behavior.
Kaddo should version the operational knowledge it installs and report whether it's aligned.

## What

- Installed agents and skills carry a `version:` front-matter field set to the Kaddo package version
  at install time (agents gain versioned front matter; skills switch their `version` from a static `1`
  to the package version). `kaddo add agents` / `kaddo add skills` write it automatically.
- `core/version.ts`: `KADDO_VERSION`, resolved robustly for source (tsx/vitest) and bundled dist.
- `core/assets.ts`: classify each catalog asset vs the installed file — `up-to-date`, `outdated`,
  `unknown-version`, `modified`, `missing`; `installedAssetsSummary` for surfacing.
- Commands `kaddo agents status` / `kaddo skills status` (`--json`) and `kaddo agents update` /
  `kaddo skills update` (`--force`). Update is safe by default: refreshes `outdated`, never overwrites
  `modified`/`unknown-version` without `--force`, leaves `missing` to `kaddo add`. Deterministic, no
  LLM, no git.
- `explain` shows a compact `## Installed Assets` block; `understand` warns when a recommended agent is
  outdated; `context-pack` carries an `installedAssets` summary; MCP resource
  `kaddo://installed-assets` (read-only, never updates).

## Scope

Version status + safe update, and surfacing. Content-diff `modified` detection (no checksums). No
auto-update, no unsafe overwrite, no code changes.

## Impact

- New `core/version.ts`, `core/assets.ts`, `commands/assets.ts`; `modules/agents.ts` (front matter),
  `skills/skills.ts` (version); `project-explain.ts`, `context-pack.ts`, `understand.ts`; MCP
  `resources.ts`; `index.ts` + command-help. Docs Installed Assets (EN/ES) + sidebar; README. Minor
  bump 3.42.0.
