# Graph edges + Docs (EN/ES) + Dogfooding

Slice **H** de la épica [[WI-046]] (Controlled Deprecation). Cierra la épica; depende de [[WI-047]]..[[WI-053]].

## Intent

Integrar los Deprecation Targets en el System Graph, documentar el lifecycle completo en EN/ES y validar
todo el flujo con dogfooding sobre un caso legacy real.

## Scope

- **Graph**: nodo `deprecation-target` (y plan si aplica); edges target↔module, target↔resource,
  target↔WI y `depends_on_removal` para blast-radius y waves; consumible por la dependency view de Admin.
- **Docs EN/ES**: lifecycle completo, multirepo, relación con Project Resources, soft deprecation,
  runbooks y las fronteras de seguridad de producción (`apps/docs/.../deprecation.md` + `es/`),
  registradas en `astro.config.mjs`.
- **Dogfooding**: un Deprecation Plan real (DEP-001) sobre un caso legacy del propio proyecto o un
  ejemplo representativo, recorriendo identify → validate → soft deprecate → observe → waves → remove
  Dev/Test → verify → runbook → (prod controlado) → observe.

## Acceptance criteria

- [x] Graph expone target/module/resource/WI edges y `depends_on_removal` (soporta AC-06/AC-14).
- [x] Docs EN/ES del lifecycle, multirepo, Resources, soft deprecation, runbooks y seguridad (AC-15).
- [x] Dogfooding: un plan real recorre el flujo end-to-end y queda como evidencia.
- [x] Tests de graph (edges correctos) sin regresiones.

## Entry points

- `packages/cli/src/core/graph.ts` — `GraphNodeType`/`GraphEdgeType`, `RESOURCE_ROLE_EDGE`.
- `apps/docs/src/content/docs/project-resources.md` (+ `es/`) como molde; `astro.config.mjs`.

## Out of scope

Lógica de dominio de A-G (ya entregada por los hermanos). No producción destructiva real sin runbook
aprobado por humano.

## Learning

La deprecacion controlada debe conectar el plan, targets, dependencias y evidencia en el grafo; los cambios sensibles conservan una aprobacion humana explicita aunque no haya ejecucion de produccion.
