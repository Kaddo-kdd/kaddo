# Discovery + Dependency Intelligence

Slice **B** de la épica [[WI-046]] (Controlled Deprecation). Depende de [[WI-047]] (Core Model).

## Intent

Construir la inteligencia que distingue "sin referencias" de "sin uso" y que ordena el retiro por
dependencias. Recoge evidencia de uso estructurada por target y deriva waves/blocked-targets de forma
explicable, apoyándose en Legacy Knowledge para la propuesta de candidatos.

## Scope

- **Usage evidence** por target: static / runtime / database / external_consumers / human_review, cada
  señal marcada como observed-fact / unknown / not-evaluated / human-confirmed. Nunca convertir
  `unknown` en `none`/`no-usage`.
- **Dependency-aware removal**: `depends_on_removal: [...]`; Core deriva **waves** (orden topológico)
  y marca `blocked` los targets cuyos dependientes aún no se retiraron. Explicable, no basado solo en
  un `priority` manual.
- **Assessment derivation**: alimentar `unused_confidence` / `blast_radius` / `reversibility` a partir
  de evidencia + topología, sin inventar un score absoluto cuando falta evidencia.
- **Candidate discovery guidance** para legacy/architecture agents: cómo proponer candidatos desde
  código/rutas/ui/jobs/Graph/Legacy Knowledge/Resources/runtime/db-metadata; discovery ≠
  materialización; el agente siempre explica el porqué.

## Acceptance criteria

- [x] Usage evidence estructurada que preserva unknown/not-evaluated sin degradar a no-usage (AC-05).
- [x] Waves y blocked targets derivados de `depends_on_removal` de forma explicable (AC-06).
- [x] Tests: dependencia transitiva (función→SP→tabla) ordena Wave1/2/3 sin recomendar la tabla primero.
- [x] Degradación segura: evidencia faltante → unknown/human-investigation-required, nunca unused.

## Validation

- `pnpm --filter @kaddo/cli test deprecation-intelligence`:
  - cadena transitiva función→SP→tabla ordena Wave1/Wave2/Wave3 (tabla al final, nunca primero).
  - ciclo o `depends_on_removal` colgante → target marcado `blocked` con razón, sin romper el resto.
  - evidencia con señales observadas de no-usage + externas inferidas → `high`; con `unknown` presente
    → cap en `medium`; sin señal fuerte → `insufficient-evidence` (nunca `unused` por ausencia).
  - señal `usage-found` → `in-use`, no candidato.
  - `targetsEligibleForRemoval` solo lista targets cuyos dependientes ya se retiraron.
- `pnpm --filter @kaddo/cli test` (suite completa) sin regresiones (aditivo sobre el Core Model).

- Legacy Knowledge (risks/unknowns/modernization candidates) como fuente de candidatos.
- `packages/cli/src/core/resources.ts` — boundaries de Project Resources como contexto de evidencia.

## Learning

La inteligencia se separó en dos capas con una línea limpia: la **evidencia de uso es un dato del
target** (vive en `deprecation.ts`, parseada junto al resto del Core Model, de forma aditiva sobre
WI-047), mientras que la **derivación** (confianza, waves, elegibilidad) vive en
`deprecation-intelligence.ts`. Así "dato = Core, razonamiento = B" y la intelligence se puede reescribir
sin tocar el modelo.

Clave de modelado para honrar "sin-referencia ≠ sin-uso": cada señal lleva dos ejes independientes —
`status` (no-usage / usage-found / unknown / not-evaluated) y `quality` (observed-fact / human-confirmed
/ inferred / unknown). La confianza nunca sube por ausencia: sin una señal fuerte de no-usage el
resultado es `insufficient-evidence`; un `unknown` explícito capea en `medium`; y `not-evaluated` (o
señal ausente) no sube ni capea pero **siempre** se nombra en el `rationale`. `requiresHumanConfirmation`
es true en todo caso salvo `in-use`: el modelo jamás "aprueba" un retiro.

Para el orden de retiro se usó Kahn sobre `depends_on_removal` con la semántica "estos deben retirarse
antes que yo" (los consumidores primero, lo consumido al final: función→SP→tabla). Los ciclos dejan a
los involucrados `blocked` sin tumbar el resto del plan, y una dependencia colgante se reporta pero no
bloquea el ordenamiento (es un hallazgo de datos, no un ciclo). La elegibilidad para revisión de retiro
es un **signal**, no una aprobación: solo lista targets cuyos dependientes ya están en un estado
retirado y que no lo estén ellos mismos.
