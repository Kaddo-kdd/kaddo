# WI-013 — Migrar el dominio público de Kaddo a kaddo.org

## Intent

### Actor

Usuario, contributor o sistema externo que accede a Kaddo mediante su sitio web, documentación, repositorio o enlaces previamente publicados.

### Problema

Kaddo ha utilizado históricamente `https://kaddo.trycatch.tv` como dominio público principal. El proyecto ahora cuenta con un dominio propio (`https://kaddo.org`) que debe convertirse en el dominio canónico. El dominio anterior no puede dejar de funcionar — debe redirigir permanentemente preservando path y query parameters.

## Target behavior

```text
kaddo.org → canonical Kaddo identity
kaddo.trycatch.tv → permanent redirect → kaddo.org (preserving path + query)
telemetry.kaddo.org → independent service (no changes)
```

## Acceptance criteria

- [x] AC-01: `https://kaddo.org` es el dominio público canónico de Kaddo
- [x] AC-02: Las referencias activas del repositorio utilizan `kaddo.org` en lugar de `kaddo.trycatch.tv`
- [x] AC-03: Requests hacia `https://kaddo.trycatch.tv/*` redirigen permanentemente a `https://kaddo.org/*`
- [x] AC-04: La redirección conserva el path original
- [x] AC-05: Los query parameters continúan disponibles después de la redirección
- [x] AC-06: Tanto el dominio nuevo como el legacy mantienen HTTPS válido
- [x] AC-07: SEO metadata, sitemap y canonical URLs utilizan `kaddo.org`
- [x] AC-08: La navegación del sitio utiliza directamente URLs de `kaddo.org`
- [x] AC-09: Las principales rutas públicas existentes continúan funcionando bajo el nuevo dominio
- [x] AC-10: Referencias históricas a `kaddo.trycatch.tv` pueden permanecer cuando su contexto lo requiera
- [x] AC-11: La migración no afecta `telemetry.kaddo.org`

## Out of scope

- Rediseño de la landing
- Cambio de branding
- Migración de DNS a otro provider
- Cambio del dominio de telemetry
- SEO strategy completa
- Actualización de publicaciones históricas externas

## Learning

### Decisiones de diseño

- **Netlify redirect con `:splat`:** La regla `[[redirects]]` en `netlify.toml` con `status = 301` y `force = true` preserva path y query parameters automáticamente. No fue necesario configurar reglas individuales por ruta.

- **Astro `site` como fuente canónica:** Cambiar `site` en `astro.config.mjs` propaga automáticamente a canonical URLs, sitemap, Open Graph y structured data (JSON-LD). Un solo cambio actualiza toda la metadata SEO.

- **Clasificación de referencias:** 22 referencias encontradas en 10 archivos. Todas eran `active-product-reference` excepto la regla de redirect (infraestructura) y el WI-013 (histórico/contextual). No hubo referencias ambiguas.

### Observaciones

- `plugin.json` contiene `homepage` y `author.url` — ambos deben actualizarse junto con el test `agent-plugin.test.ts` que valida esos valores exactos.

- La build del sitio (141 páginas) confirma que no hay links rotos internos tras la migración. El sitemap generado usa `kaddo.org` en todas las URLs.

- AC-06 (HTTPS) depende de la configuración DNS/Netlify que está fuera del repositorio — el redirect y el site config están listos, pero HTTPS requiere que `kaddo.org` esté configurado en Netlify con certificado.
