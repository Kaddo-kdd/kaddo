# WI-039 — Admin resource management

Hijo de [[WI-035]]. Depende de [[WI-036]]. Gestión visual completa de recursos en el Admin.

## Scope
1. Sección de primer nivel **"Resources"** en el Admin (nav): list, inspect, create, edit, delete.
2. Resource detail: identity/type/provider/purpose/scope/environments/interfaces/boundaries/auth refs/related modules/related WIs — sin secretos.
3. CRUD vía admin-server → core-adapter → Core (sin schema/validación duplicada en el frontend; delete con confirmación de referencias).
4. **Multirepo**: agrupar por scope (System / por módulo); mostrar recursos compartidos (used by: módulos).

## Out of scope
Core (WI-036); CLI (WI-037); MCP (WI-038); graph/docs (WI-040). Portal operacional, ejecución.

## Acceptance criteria
- [x] AC-01 — List/inspect: la sección Resources lista y muestra el detalle (sin secretos).
- [x] AC-02 — Create/edit/delete: CRUD desde el Admin vía Core; delete con confirmación de referencias.
- [x] AC-03 — Related: el detalle muestra WIs y módulos relacionados.
- [x] AC-04 — Multirepo: agrupación por scope y recursos compartidos (used by).
- [x] AC-05 — No duplicated schema: la validación/reglas viven en Core, no en el frontend.
- [x] AC-06 — Backward compatible: proyectos sin resources muestran la sección vacía sin romper.

## Validation
- Admin → Resources → Create (mismo recurso) → admin-server → Core → artifact.
- Editar/borrar desde Admin; delete muestra referencias.
- Proyecto multirepo: recursos agrupados por scope; compartido muestra "used by".

## Definition of Done
Admin ofrece gestión visual completa (CRUD + detalle + relacionados + multirepo) vía Core; sin secretos; tests (adapter/contrato) + verificación visual; Evidence; Verification; Learning.

## Implementation handoff guidance
Espejar `WorkItemNew`/`WorkItemEditor` + los writes del admin-server (VS-099) y el adapter a Core. Reutilizar el patrón de navegación/secciones del detalle de WI (WI-034).

## Learning

- **CRUD completo reutilizando el patrón de initiatives.** admin-server: `coreRoute` (list) +
  `writeHandler`+zod (create/update/delete), adapter que envuelve el contrato Core de WI-036 y mapea
  `ResourceWriteError`→`CoreError`. admin: dos rutas (`Resources` lista+crear, `ResourceDetail`
  detalle+edit+delete) con react-query, nav item nuevo.
- **Reglas en Core, no en el frontend (AC-05).** El Admin solo arma el `ResourceInput` y llama a la
  API; validación, secret-safety y delete-safety viven en Core. Verificado: crear con `PWD=leak` en
  refs nunca persiste ni muestra el valor (0 leaks a través de todo el stack Admin).
- **Delete en dos pasos.** El detalle pide primero el preview (`DELETE ?confirm=false` → referencias),
  las muestra ("no se eliminan"), y solo con "Confirm delete" hace `?confirm=true`. El WI referenciado
  queda intacto.
- **Multirepo por agrupación.** `groupByScope` agrupa recursos en "System" + por módulo; en single-repo
  se ve plano. `modules` se muestra como "used by".
- **Fix de status.** `RESOURCE_NOT_FOUND`/`NOT_FOUND`→404, `DUPLICATE`→409, `VALIDATION_FAILED`→400 en
  `statusForCode` (antes caían en 500).
