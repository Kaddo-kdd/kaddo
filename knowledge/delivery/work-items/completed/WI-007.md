# Documentation Kaddo-Native Transition

## Current behavior

1. `CONTRIBUTING.md:76-81` — Section "OpenSpec: define before you build" directs contributors
   to create `proposal.md`, `design.md`, `spec.md` and `tasks.md` under
   `openspec/changes/<change-id>/`.

2. `apps/docs/src/content/docs/playbook/tool-examples.md:32-41` (EN) — Section "Kaddo +
   OpenSpec" presents OpenSpec as a current integration pattern:
   `OpenSpec change → Kaddo Work Item → Guard ownership`.

3. `apps/docs/src/content/docs/es/playbook/tool-examples.md:34-44` (ES) — Same section in
   Spanish: `Cambio de OpenSpec → Work Item de Kaddo → ownership de Guard`.

4. `README.md:120` — Playbook link list includes "OpenSpec" in the description:
   `GitHub Issues, Jira/Linear, OpenSpec, agent frameworks, LLM chats`.

## Target behavior

1. `CONTRIBUTING.md` — Replace the OpenSpec section with a "Build Contract" section that
   directs contributors to use the Kaddo Work Item lifecycle (draft → refine → ready →
   handoff → implement → verify → complete). Reference the Build Contract and Implementation
   Handoff skills. Add a note that OpenSpec artifacts remain as historical reference under
   `openspec/` but are no longer the active workflow.

2. `tool-examples.md` (EN) — Replace "Kaddo + OpenSpec" section with "Kaddo + Build Contract"
   explaining the native lifecycle pattern. OpenSpec becomes a historical footnote, not a
   recommended pattern.

3. `tool-examples.md` (ES) — Same replacement in Spanish.

4. `README.md:120` — Update description to remove "OpenSpec" and reference "Build Contract"
   instead.

## Acceptance criteria

- [ ] AC1: CONTRIBUTING.md no longer directs contributors to create OpenSpec artifacts
- [ ] AC2: CONTRIBUTING.md describes the Build Contract / Work Item lifecycle as the standard
      contributor workflow
- [ ] AC3: tool-examples.md (EN) replaces "Kaddo + OpenSpec" with "Kaddo + Build Contract"
- [ ] AC4: tool-examples.md (ES) replaces "Kaddo + OpenSpec" with the equivalent in Spanish
- [ ] AC5: README.md playbook link description no longer mentions OpenSpec
- [ ] AC6: OpenSpec is positioned as historical reference, not deleted from the repository

## Validation

- Text review: all 4 files updated, no OpenSpec references as active workflow
- `pnpm --filter @kaddo/cli run test` passes (no code changes, but confirms no regressions)
- `grep -r "OpenSpec" CONTRIBUTING.md README.md apps/docs/src/content/docs/playbook/tool-examples.md apps/docs/src/content/docs/es/playbook/tool-examples.md` — only historical references remain

## Out of scope

- Deleting the `openspec/` directory or its contents
- Changing any CLI code or agent behavior
- Updating other documentation pages beyond the 4 listed files

## Learning

1. El lifecycle completo para un chore de documentación fue fluido y proporcional — no se
   necesitó handoff pesado porque no hay deliberación de diseño. Esto refuerza H6
   (proporcionalidad): el lifecycle escala según la complejidad del WI.

2. La transición de OpenSpec a Build Contract en documentación no generó fricción nueva —
   los 4 archivos fueron ediciones directas con scope claro. El refinamiento con ACs
   explícitos (6 ACs) fue útil para validar completitud sin overhead excesivo.

3. La coexistencia de OpenSpec como referencia histórica (AC6) es importante: eliminar los
   artefactos existentes rompería la trazabilidad de cambios anteriores. El patrón de
   "historical note" en la documentación es suficiente para comunicar la transición.
