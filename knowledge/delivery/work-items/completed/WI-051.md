# Soft Deprecation + Observation

Slice **E** de la épica [[WI-046]] (Controlled Deprecation). Depende de [[WI-047]] (y se integra con D/F).

## Intent

Materializar el principio "soft deprecation antes del retiro físico": estrategia de soft deprecation
por target, ventana de observación con criterios de salida, transiciones por ambiente y el desenlace
`deprecated-retained`.

## Scope

- **Soft deprecation strategy** por target: strategy/mechanism (feature-flag, hide UI, disable route,
  deprecation warning, stop scheduler, remove caller, stop writes, read-only, telemetry, manual…) —
  sin obligar a que todo sistema soporte feature flags.
- **Observation window**: `observation_window_days` + `exit_criteria`; al cumplirse, el target queda
  **eligible for removal review** (NO auto-removido; la eliminación es humana).
- **Environment transitions**: cómo avanza el estado por ambiente (p. ej. dev/test removed mientras
  production sigue active).
- **Retention outcome**: `deprecated-retained` (stop writes + retener histórico) sin bloquear el plan.

## Acceptance criteria

- [x] Lifecycle soft-deprecated → disabled → dev/test removal → prod readiness → observation →
      completion antes del decommission físico (AC-07).
- [x] Observation window + exit criteria; cumplirlos deja al target eligible, no removido (AC-09).
- [x] `deprecated-retained` como desenlace válido sin bloquear el plan (refuerza AC-13).
- [x] Tests (window cumplida → eligible; retained no bloquea; transición por ambiente).

## Validation

- `pnpm --filter @kaddo/cli test deprecation-observation`:
  - lifecycle no permite saltar soft-deprecated → completed/removed (ordering AC-07).
  - eligible solo con ventana cumplida Y todos los exit criteria met; antes de la ventana, no; sin
    criterios declarados, no (nunca "all met" por ausencia) (AC-09).
  - `deprecated-retained` terminal que NO bloquea waves ni elegibilidad de dependientes (AC-13).
  - `environmentSummary` distingue Dev/Test removed de production active.
  - `planIntelligence` expone observación por target.
- Suites completas cli + mcp sin regresiones.

## Entry points

- Core Model lifecycle/env-state de [[WI-047]].
- Project Resources boundaries (stop writes / read-only) de resources.ts.

## Out of scope

Mutación/surfaces (C), runbooks de producción (F), Admin (G), graph/docs (H).

## Learning

La observación es **determinista e inyectable en el tiempo**: `observationStatus(target, now)` recibe
`now` (default `new Date()`), lo que hace los tests reproducibles sin mockear el reloj. La elegibilidad
para revisión de retiro exige ventana cumplida **y** todos los exit criteria `met`; y —coherente con el
principio rector de la épica— **nunca** se finge elegibilidad por ausencia: sin criterios declarados el
resultado es "no elegible" con razón explícita (`criteriaTotal > 0 && met === total`), igual que
`not-evaluated`/`unknown` en la evidencia de uso (B). La elegibilidad es un *signal* de revisión, no una
aprobación: el `reasons` lo deja explícito ("human decision").

Se mantuvo la línea de slices: el **dato** (strategy/mechanism/started_at/observation_window_days/
exit_criteria) vive en el target del Core Model (`deprecation.ts`), y el **razonamiento** en un módulo
nuevo `deprecation-observation.ts`; `planIntelligence` (B) lo compone en `TargetIntelligence.observation`
para que CLI `analyze` y MCP lo expongan sin esfuerzo extra. El desenlace `deprecated-retained` ya era
estado retirado desde B (`isRetiredLifecycle`), así que "retenido no bloquea el plan" cayó solo: sus
dependientes se desbloquean y las waves resuelven sin `blocked`. `environmentSummary` formaliza que un
retiro en Dev/Test (`removedInDevTest`) nunca se lea como cambio de producción (`productionActive`
independiente). No se forzó ningún mecanismo (feature flags opcional): `strategy` es texto libre con una
lista advisory `SOFT_DEPRECATION_STRATEGIES`.
