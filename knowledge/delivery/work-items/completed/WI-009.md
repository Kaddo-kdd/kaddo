# OpenSpec Removal

## Current behavior

1. `openspec/` directory exists in the working tree with 312 files (templates, README, 99+
   historical change folders). No runtime, package, CI, or agent dependency exists on these
   files.

2. CONTRIBUTING.md, tool-examples EN/ES contain historical notes referencing `openspec/`
   as a directory that "remains" — will be inaccurate after deletion.

3. `knowledge/delivery/build-contract.md` and `knowledge/delivery/migration/` contain
   historical references explaining the OpenSpec → Kaddo transition. These are migration
   history, not operational dependencies.

## Target behavior

1. `openspec/` directory removed from working tree. History preserved in Git.

2. Historical notes in CONTRIBUTING.md and tool-examples EN/ES updated to reference Git
   history instead of a directory path.

3. All migration-history and completed-WI references to OpenSpec remain as-is (P4: historical
   references are allowed).

4. Operational OpenSpec dependency inventory = 0.

## Acceptance criteria

- [ ] AC1: `openspec/` directory does not exist in the working tree
- [ ] AC2: CONTRIBUTING.md references Git history, not `openspec/` directory
- [ ] AC3: tool-examples EN/ES reference Git history, not `openspec/` directory
- [ ] AC4: No agent, skill, or prompt instructs creating/using OpenSpec artifacts
- [ ] AC5: No package.json, CI workflow, or script depends on OpenSpec
- [ ] AC6: Full test suite passes after removal
- [ ] AC7: Operational dependency inventory = 0
- [ ] AC8: Historical references in migration docs and completed WIs remain intact

## Learning

1. La eliminación fue limpia — cero dependencias operacionales confirmadas tanto por VS-108
   (inventory) como por VS-112 (dogfooding). El trabajo previo de inventariar y transicionar
   hizo que el removal fuera trivial.

2. La self-hosting verification (section 27) funcionó: VS-114 se construyó como WI-009
   usando el lifecycle Kaddo-nativo, demostrando que Kaddo puede eliminar OpenSpec usando Kaddo.

3. La distinción entre referencia operacional e histórica (section 22) fue crucial. Un simple
   `grep -r "OpenSpec"` encontró 13 archivos, pero todas son referencias históricas legítimas
   en migration docs, completed WIs y el dogfooding report. El release gate mide dependencias
   operacionales, no ocurrencias textuales.
