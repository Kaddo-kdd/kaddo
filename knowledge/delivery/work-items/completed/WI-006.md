# Fix responsibility matrix rendering to include all agents

## Current behavior

`renderResponsibilityMatrixMarkdown()` in `packages/cli/src/agents/responsibility.ts:401-428`
hardcodes an `order` array with 12 agents. `RESPONSIBILITY_MATRIX` contains 23 agents. The
rendered Markdown table silently omits 11 agents:

- bootstrap-agent
- stack-agent
- standards-agent
- security-agent
- module-design-agent
- module-context-agent
- adr-agent
- capsule-agent
- graph-agent
- git-strategy-agent
- legacy-agent

## Target behavior

`renderResponsibilityMatrixMarkdown()` renders all 23 agents from `RESPONSIBILITY_MATRIX` in a
logical order. No agent is silently omitted.

## Acceptance criteria

- The rendered Markdown table includes all agents present in RESPONSIBILITY_MATRIX
- The order groups agents logically (business → product → tech → delivery → utilities)
- Existing test `renders the matrix as markdown` passes and verifies completeness

## Validation

- `pnpm --filter @kaddo/cli run test` passes
- `renderResponsibilityMatrixMarkdown()` output contains all 23 agent names

## Out of scope

- Changing agent responsibilities or boundaries
- Adding new agents
- Modifying the runtime responsibility injection (works correctly for all agents)

## Learning

1. El handoff para un fix pequeño fue ligero y proporcional — no se necesitó deliberación
   de diseño ni análisis extenso. Esto valida H6 (proporcionalidad).

2. `kaddo verify` reveló fricción significativa: sin `.kaddo/modules.yml`, el cross-repo
   analysis genera false-positive blockers. Esto se resuelve naturalmente cuando WI-008
   instale los módulos del proyecto.

3. La verificación de ACs requiere input humano/agente — `kaddo verify` recolecta evidencia
   de git automáticamente pero no puede determinar si un AC pasó solo con test output. Esto
   es intencional pero vale la pena documentar como expectativa.
