# WI-016 — Extender consentimiento de telemetría a interfaces MCP y LLM

## Intent

### Actor

Usuario de Kaddo que interactúa principalmente vía MCP/LLM.

### Problema

WI-015 implementó el modelo de consentimiento de tres estados, pero `ensureTelemetryConsent()` depende de `isInteractive()` que requiere TTY. Los usuarios que usan Kaddo vía MCP (la ruta de uso principal) nunca reciben una oportunidad de consentimiento porque MCP no tiene TTY.

## Acceptance criteria

- [x] AC-01: Shared Consent — CLI y MCP comparten el mismo estado de consentimiento en `.kaddo/config.yml`
- [x] AC-02: Init Opportunity — `kaddo init` ofrece consentimiento inmediatamente después de la configuración
- [x] AC-03: MCP Status Tool — `kaddo_telemetry_status` expone estado de consentimiento, registro y eventos pendientes
- [x] AC-04: MCP Consent Notice — `kaddo_project_status` incluye aviso de consentimiento cuando `unset` y sin diferimiento
- [x] AC-05: MCP Status Notice — `kaddo_telemetry_status` incluye aviso cuando consent es `unset` sin diferimiento activo
- [x] AC-06: Explicit MCP Action — `kaddo_set_telemetry_consent` requiere `confirm: true` para aplicar
- [x] AC-07: Preview Without Confirm — sin `confirm`, el tool retorna preview del efecto sin ejecutar
- [x] AC-08: Enable Via MCP — `consent: 'enabled'` con `confirm: true` activa telemetría
- [x] AC-09: Disable Via MCP — `consent: 'disabled'` con `confirm: true` desactiva telemetría permanentemente
- [x] AC-10: Not Now Deferral — `consent: 'not-now'` con `confirm: true` difiere 24 horas
- [x] AC-11: Deferral Expiry — después de 24h el aviso reaparece en responses de status
- [x] AC-12: Non-interactive Safety — MCP nunca dispara prompts interactivos de consentimiento
- [x] AC-13: Cross-interface Consistency — habilitar vía CLI es visible desde MCP y viceversa
- [x] AC-14: Invalid Consent Rejection — valores inválidos retornan error descriptivo
- [x] AC-15: Documentation — docs EN/ES actualizadas con sección MCP/LLM

## Out of scope

- Cambios al Telemetry Service
- Consent re-prompt basado en consentVersion upgrade
- UI de admin para consentimiento
- Tracking de decisiones de consentimiento

## Learning

### Decisiones de diseño

1. **Tools explícitos en lugar de inyección automática:** En vez de intentar inyectar consentimiento en cada tool MCP, se crearon dos herramientas dedicadas (`kaddo_telemetry_status`, `kaddo_set_telemetry_consent`). Esto respeta la naturaleza explícita de las interacciones MCP donde el LLM decide cuándo y cómo presentar información al usuario.

2. **Consent notice en project status:** Se inyecta un `telemetryNotice` en `kaddo_project_status` cuando consent es `unset` y no hay diferimiento activo. Esto asegura que el LLM ve la información de consentimiento durante el flujo natural de exploración de proyecto sin requerir una llamada separada.

3. **Patrón confirm similar a markWorkItemReady:** El tool `kaddo_set_telemetry_consent` sigue el mismo patrón de preview/confirm que `kaddo_mark_work_item_ready` y `kaddo_modules_discover`. Sin `confirm=true` muestra qué pasará; con `confirm=true` ejecuta. Esto mantiene consistencia en la UX MCP.

4. **Diferimiento local en JSON separado:** El estado de diferimiento se almacena en `.kaddo/telemetry-deferred.json` en vez de en `config.yml`. Esto evita escribir en config para un estado temporal que expira automáticamente, y mantiene config como la fuente de verdad para decisiones permanentes.

5. **Consent en kaddo init:** Se movió el prompt de consentimiento al final de `kaddo init`, después de crear todos los archivos. Esto captura la decisión en el momento más temprano posible sin interrumpir el flujo de inicialización.

### Observaciones

- El módulo `telemetry-consent.ts` se mantiene como módulo puro compartido — tanto CLI (`preAction`) como MCP (`tools.ts`) importan las mismas funciones.
- Las exports se agregan a `core.ts` para que MCP pueda importar vía `@kaddo/cli/core`.
- 9 tests nuevos en MCP + 5 tests nuevos en CLI cubren: status, enable, disable, defer, expiración, cross-interface, preview, rechazo de valores inválidos.
- `.kaddo/telemetry-deferred.json` está cubierto por el gitignore de `.kaddo/`.
