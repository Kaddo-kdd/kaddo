# WI-037 — CLI resource management

Hijo de [[WI-035]]. Depende de [[WI-036]] (Core mutations). Expone CRUD desde la CLI.

## Scope
1. `kaddo resources create` interactivo (Minimum Sufficient Knowledge: name/type/provider/scope; luego opcional "add interfaces?"). No un formulario obligatorio.
2. `kaddo resources update <id>` (editar campos; no-lossy vía Core).
3. `kaddo resources delete <id>` → muestra referencias (Core) y pide confirmación (`-y` para automatización).
4. Mantener `list`/`get`.

## Out of scope
MCP/LLM (WI-038); Admin (WI-039); graph/docs (WI-040). Writes propios fuera de Core.

## Acceptance criteria
- [x] AC-01 — create: crea un recurso canónico vía Core, capturando solo lo mínimo suficiente.
- [x] AC-02 — update: modifica un recurso existente sin pérdida.
- [x] AC-03 — delete: muestra referencias y exige confirmación; `--yes` la salta.
- [x] AC-04 — Consistency: usa las reglas de Core (sin re-validar/escribir por su cuenta); `--json` donde aplique.
- [x] AC-05 — Backward compatible: list/get siguen igual.

## Validation
- `kaddo resources create` (Supabase Main/database/supabase/system) → archivo canónico; `get` lo devuelve.
- `update` agrega una interfaz sin perder el resto.
- `delete` de un recurso referenciado → preview + confirmación; con `--yes` borra.

## Definition of Done
CLI ofrece create/update/delete usando Core; interactivo y mínimo suficiente; delete con safety; tests de comando; Evidence; Verification; Learning.

## Implementation handoff guidance
Prompts con `utils/ui.ts` (`text`/`select`/`confirm`) como `kaddo create`. Llamar a `resource-write.ts` de WI-036; nunca generar Markdown en el comando.

## Learning

- **Comando híbrido flags+interactivo.** `create` es no-interactivo con `--title/--type` (testeable y
  automatable) y cae a prompts (`text`/`select`) solo con TTY y campos faltantes — Minimum Sufficient
  Knowledge, no un formulario. `update` toma solo los campos a cambiar; `delete` lista referencias y
  exige confirmación (o `--yes`; en no-TTY sin `--yes` rehúsa).
- **Thin wrapper sobre Core.** Los tres comandos delegan todo a `resource-write.ts` (WI-036); no
  generan Markdown ni revalidan. El test del comando solo verifica el cableado.
- **Fix de consistencia read↔write.** El write guarda `purpose` en la sección `# Purpose` del body,
  pero el read model lo leía del frontmatter → `getResource.purpose` daba null tras un update. Se
  arregló para leer el purpose del frontmatter **o** de la sección `# Purpose`. Buen recordatorio de
  mantener alineados serializador y parser.
- **Delete safety visible en CLI.** Antes de borrar, el comando imprime "referenced by: WI-xxx" y
  avisa que no se tocan esas referencias; el borrado deja los WIs intactos.
