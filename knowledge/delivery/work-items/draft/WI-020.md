# WI-020 — Initiative intelligence y Admin

> Hijo de [WI-017](./WI-017.md) (epic). Cubre las fases 5-6: `initiative-agent`, gap analysis, candidatos incrementales, completion readiness con human gate, e integración con `backlog-agent`; más la sección Initiatives en Admin. Aquí también aterrizan las superficies `analyze`/`complete` (CLI + MCP) que WI-019 dejó fuera.

## Intent

### Problema

Con Core (WI-018) y superficies CRUD (WI-019), Kaddo aún no puede responder "¿qué falta para completar INI-001?" ni evaluar si una Initiative está realmente completa, ni gestionarla visualmente. Falta la capa de inteligencia (fundamentada, no inventada) y la superficie Admin.

### Goal

Agregar análisis de cobertura/gaps fundamentado en conocimiento existente, generación incremental de candidates, evaluación de completion readiness human-gated, integración con backlog-agent, y la sección Initiatives en Admin consumiendo Core.

## Scope

- **initiative-agent** (o responsabilidad equivalente): entender la Initiative, evaluar cobertura, descomponer en candidates, detectar trabajo faltante y candidatos duplicados/solapados, considerar estado actual del proyecto, evaluar completion readiness, sugerir candidates. No escribe código, no materializa sin humano, no completa autónomamente.
- **Gap analysis** (AC-16/17/18): analizable múltiples veces durante el lifecycle; considera estado actual; propone candidates nuevos con source signals/evidencia (no inventa trabajo).
- **Completion analysis** (AC-19/20): detecta scope comprometido sin cobertura aunque todos los WIs estén completed; produce completion candidate → human review → completed. Nunca completa automáticamente.
- **Surfaces** `analyze`/`complete`: CLI (`kaddo initiative analyze|complete`) + MCP (`kaddo_analyze_initiative`, `kaddo_complete_initiative`) con confirm.
- **Backlog agent** (AC-21): distinguir idea nueva → ¿Initiative existente? → sí (candidate/asociación) / no (standalone WI o new Initiative candidate). Sin obligar a clasificar todo.
- **Admin** (AC-15): sección Initiatives — list, lifecycle/status, horizon/priority, create, edit, candidates, WIs asociados, planning coverage, delivery progress, trigger/inspect analysis, materialize candidates, completion readiness. Consume Core-adapter; WIs standalone se muestran normalmente.

## Out of scope

- external_links / imported WI association / graph / docs (WI-021).
- Analytics de business outcome inexistentes.

## Acceptance criteria

- [ ] AC-15 — Admin: listar, consultar, crear/editar y seguir Initiatives.
- [ ] AC-16 — Gap Analysis: analizar una Initiative contra el estado actual del proyecto.
- [ ] AC-17 — Incremental Candidates: proponer nuevos WI candidates después de iniciado el delivery.
- [ ] AC-18 — Grounded Candidates: nuevos candidates con source signals o evidencia del gap.
- [ ] AC-19 — Completion Analysis: detectar scope comprometido sin cobertura aunque todos los WIs estén completed.
- [ ] AC-20 — Human Completion: completion requiere confirmación humana.
- [ ] AC-21 — Backlog Integration: backlog-agent sugiere standalone WI, existing Initiative o new Initiative candidate.

## Validation

- `INI-001` con todos los WIs completed + `analyze` → no se marca completa, gap reportado, candidate sugerido con source signal.
- Scope cubierto + WIs completed + verificación OK + sin gaps → ready for completion → requiere confirmación → completed.
- MCP: "What is missing to complete INI-001?" → context → analysis → coverage → missing scope → candidate proposals, sin crear WIs hasta pedirlo.
- Admin: list/detail/candidates/related WIs/planning+delivery progress/analysis/completion desde Core (sin lógica duplicada en Admin).

## Dependencies

- WI-018 (Core), WI-019 (surfaces CRUD/context). Agentes: [backlog-agent](knowledge/agents/delivery/backlog-agent.md). Admin→Core adapter ([core-adapter.ts](packages/admin-server/src/core-adapter.ts)).
