# WI-021 — Initiative external traceability, graph, docs y E2E

> Hijo de [WI-017](./WI-017.md) (epic). Cubre las fases 7-8: trazabilidad externa provider-neutral, grafo de trazabilidad, documentación EN/ES y dogfooding end-to-end. Cierra el epic.

## Intent

### Problema

Con Initiatives operables e inteligentes (WI-018/019/020), falta conectarlas con planificación externa (Jira/ADO/GitHub) de forma provider-neutral, representarlas en el Knowledge Graph, documentarlas y validar el flujo completo con Kaddo mismo.

### Goal

Dejar la trazabilidad externa preparada y utilizable (sin sincronización bidireccional ni import completo), extender el grafo, documentar EN/ES y ejecutar un escenario E2E de dogfooding.

## Scope

- **external_links** (AC-22): referencias provider-neutral `{ integration, external_id, external_type, url }` en el artifact de Initiative. No asumir `Initiative = Jira Epic`.
- **External status as signal** (AC-23): un estado externo (p.ej. Epic = Done) no cambia el lifecycle de la Initiative; se trata como señal; Kaddo conserva su lifecycle, análisis y human gate.
- **Imported WI association** (AC-24): cuando un WI importado se relaciona claramente con una Initiative, Kaddo sugiere la asociación (confirmación humana salvo regla determinística aprobada). Boundary adapter-neutral: `Provider → Adapter → normalized metadata → Core`, sin lógica de Jira en Initiative Core.
- **Graph** (AC-25): extender el Knowledge Graph con Initiative→capability, Initiative→WI, Initiative→external planning item, WI→Initiative, Candidate→Initiative, sin romper graph consumers existentes.
- **Docs** (AC-27): EN/ES — Initiative lifecycle, roadmap relationship, standalone WIs, CLI, MCP, Admin, external traceability.
- **E2E dogfooding**: ejecutar el flujo completo usando Kaddo sobre su propio repo; recolectar Implementation Evidence; capturar Learning del modelo de Initiative.

## Out of scope

- Sincronización bidireccional completa con Jira/ADO/GitHub.
- Propagación automática de estado externo.
- Capability completa de discover/import de ExternalPlanningItem.
- Lifecycle de Initiative específico por proveedor.

## Acceptance criteria

- [ ] AC-22 — External Links: una Initiative mantiene referencias provider-neutral a Jira u otras integraciones.
- [ ] AC-23 — External Status Isolation: cambios de status externos no modifican automáticamente el lifecycle.
- [ ] AC-24 — Imported WI Association: Kaddo asocia o sugiere asociación de un imported WI con una Initiative.
- [ ] AC-25 — Graph: relaciones Initiative → WI/capability/external representables sin romper graph consumers.
- [ ] AC-27 — Documentation: docs EN/ES de Initiative lifecycle, roadmap relationship, standalone WIs, CLI, MCP, Admin y external traceability.

## Validation

- `INI-001 ↔ Jira Epic AUTH-20`; import `AUTH-21 (parent AUTH-20) → WI-021`; Kaddo sugiere `WI-021 → INI-001`.
- Cambiar el Epic externo a Done no cambia `INI-001` a completed.
- Graph export incluye nodos/edges de Initiative sin romper consumers existentes.
- Docs EN/ES construyen (apps/docs build verde) y cubren las superficies.
- E2E: crear INI, materializar candidates, implementar, verificar, analizar, completar con human gate — sobre el repo de Kaddo.
