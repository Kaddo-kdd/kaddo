# WI-022 — Initiative Admin: sección de gestión visual

> Hijo de [WI-017](./WI-017.md) (epic). Cubre la fase 6 (AC-15), separada de [WI-020](../completed/WI-020.md) el 2026-10-03 para darle verificación en navegador. Consume el Initiative Core (WI-018) y las superficies/analysis (WI-019/020) vía el Admin→Core adapter.

## Intent

### Problema

El Initiative Core, sus superficies CLI/MCP y la inteligencia (gap/completion analysis) existen (WI-018/019/020), pero el Admin no tiene forma de gestionar Initiatives visualmente. Falta la sección Initiatives en el Admin.

### Goal

Agregar una sección Initiatives al Admin que consuma el Core (sin lógica duplicada): listar, ver detalle, candidates, WIs asociados, planning/delivery progress, análisis y completion readiness — y crear/editar Initiatives.

## Scope

- **Contracts** (`packages/admin-server/src/contracts/schemas.ts`): schemas Zod para Initiative list item, detail (con progress + candidates + WIs asociados), analysis y completion readiness.
- **Core-adapter** (`core-adapter.ts`): `getInitiativesListAdmin`, `getInitiativeDetailAdmin` (incluye progress + analysis + completion), y las mutaciones `createInitiativeAdmin` / `updateInitiativeAdmin` reutilizando `@kaddo/cli/core`.
- **Server** (`server.ts`): rutas GET (`/api/v1/admin/initiatives`, `/api/v1/admin/initiatives/:id`) y las POST/PUT para create/update, siguiendo el patrón `coreRoute`.
- **API client** (`packages/admin/src/lib/api.ts`): métodos + tipos.
- **Rutas React**: `routes/Initiatives.tsx` (list) y `routes/InitiativeDetail.tsx` (detail con progress, candidates, WIs asociados, analysis y completion readiness). Wiring en `App.tsx` (TanStack Router) y entrada en `Sidebar.tsx`.
- **Standalone WIs** (AC-19 del epic / nota): los WIs sin Initiative se siguen mostrando normalmente en su propia vista; no se tratan como error.

## Out of scope

- Nueva lógica de dominio (vive en Core; el Admin solo presenta/consume).
- external_links / graph / docs / E2E (WI-021).

## Acceptance criteria

- [ ] AC-15 — Admin: el Admin permite listar, consultar, crear/editar y seguir Initiatives (lifecycle/status, horizon/priority, candidates, WIs asociados, planning coverage, delivery progress, análisis y completion readiness), consumiendo Core.

## Validation

- Levantar el Admin dev server y verificar **en navegador**: la lista de Initiatives carga; el detalle muestra status, candidates, WIs asociados, planning/delivery progress, análisis y completion readiness.
- Crear una Initiative desde el Admin y verla aparecer en la lista.
- WIs standalone (sin Initiative) siguen mostrándose en su vista sin errores.
- Build del Admin verde (`tsc -b && vite build`) + tests existentes del Admin sin regresión.

## Dependencies

- WI-018 (Core), WI-019 (surfaces/context), WI-020 (analysis/completion). Admin→Core adapter ([core-adapter.ts](packages/admin-server/src/core-adapter.ts)), patrón de rutas existente ([WorkItems.tsx](packages/admin/src/routes/WorkItems.tsx)).
