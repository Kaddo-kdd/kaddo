# Production Runbooks

Slice **F** de la épica [[WI-046]] (Controlled Deprecation). Depende de [[WI-047]], [[WI-050]].

## Intent

Para cambios sensibles de producción (p. ej. retiro de un objeto de BD), generar un **Production
Runbook** versionable y hacer cumplir la frontera: propuesta de paso → confirmación humana → ejecución
→ evidencia → siguiente. Ninguna operación destructiva de producción se ejecuta de forma autónoma.

## Scope

- Artifact `knowledge/delivery/runbooks/RB-xxx-<slug>.md` con secciones: Purpose, Preconditions,
  Dependencies, Backup/Recovery, Impact, Execution Order, Commands, Expected Results, Validation,
  Rollback, Abort Conditions, Observation Window, Evidence, Approval. No puede ser solo comandos
  destructivos.
- **Generation context**: a partir del target/resource/evidencia/dependencias (Dev/Test ya verificado).
- **Controlled execution**: proponer siguiente paso → humano confirma → ejecuta → captura resultado →
  valida → siguiente. Prohibido DROP/DELETE/schema-mutation no atendidos y runbooks de prod autónomos.
- **Post-change observation**: production-changed → observing → completed.

## Acceptance criteria

- [ ] Cambios sensibles de prod generan un Runbook con preconditions/backup/execution/validation/
      rollback/abort/evidence (AC-11).
- [ ] Ninguna operación destructiva de prod se ejecuta en silencio o por inferencia autónoma (AC-12).
- [ ] Post-change observation hasta cumplir criterios → completed.
- [ ] Tests (runbook generado tiene todas las secciones; falta backup/rollback → inválido).

## Entry points

- Patrón de artifact versionable de los Work Items (serialize/parse).
- `packages/cli/src/core/resources.ts` — boundary prod write/destructive del Resource.
- Integración con Evidence/Verification existente.

## Out of scope

Modelo (A), discovery (B), surfaces (C), soft/observación general (E), Admin (G), docs (H).
