# Soft Deprecation + Observation

Slice **E** de la épica [[WI-046]] (Controlled Deprecation). Depende de [[WI-047]] (y se integra con D/F).

## Intent

Materializar el principio "soft deprecation antes del retiro físico": estrategia de soft deprecation
por target, ventana de observación con criterios de salida, transiciones por ambiente y el desenlace
`deprecated-retained`.

## Scope

- **Soft deprecation strategy** por target: strategy/mechanism (feature-flag, hide UI, disable route,
  deprecation warning, stop scheduler, remove caller, stop writes, read-only, telemetry, manual…) —
  sin obligar a que todo sistema soporte feature flags.
- **Observation window**: `observation_window_days` + `exit_criteria`; al cumplirse, el target queda
  **eligible for removal review** (NO auto-removido; la eliminación es humana).
- **Environment transitions**: cómo avanza el estado por ambiente (p. ej. dev/test removed mientras
  production sigue active).
- **Retention outcome**: `deprecated-retained` (stop writes + retener histórico) sin bloquear el plan.

## Acceptance criteria

- [ ] Lifecycle soft-deprecated → disabled → dev/test removal → prod readiness → observation →
      completion antes del decommission físico (AC-07).
- [ ] Observation window + exit criteria; cumplirlos deja al target eligible, no removido (AC-09).
- [ ] `deprecated-retained` como desenlace válido sin bloquear el plan (refuerza AC-13).
- [ ] Tests (window cumplida → eligible; retained no bloquea; transición por ambiente).

## Entry points

- Core Model lifecycle/env-state de [[WI-047]].
- Project Resources boundaries (stop writes / read-only) de resources.ts.

## Out of scope

Mutación/surfaces (C), runbooks de producción (F), Admin (G), graph/docs (H).
