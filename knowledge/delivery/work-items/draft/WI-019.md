# WI-019 — Initiative surfaces: CLI y MCP

> Hijo de [WI-017](./WI-017.md) (epic). Cubre la fase 4 del Handoff: exponer el Core de Initiatives (WI-018) vía CLI y MCP. Incluye CRUD, lectura, contexto y materialización de candidates. El análisis inteligente (analyze/complete) vive en WI-020.

## Intent

### Problema

Con el Core de Initiatives en su lugar (WI-018), no hay forma de operarlas desde ninguna interfaz. El usuario y los agentes necesitan crear, consultar, actualizar, ver progreso y materializar candidates desde CLI y MCP.

### Goal

Agregar superficies CLI y MCP que deleguen en el Core, con confirmación humana en las mutaciones por MCP.

## Scope

- **CLI**: `kaddo initiative create|list|show|update|progress|candidates|materialize` (gramática final sujeta a convenciones; delega en Core).
- **MCP (lectura)**: `kaddo_list_initiatives`, `kaddo_get_initiative`, `kaddo_get_initiative_context`, `kaddo_get_initiative_progress`.
- **MCP (mutación, confirm=true)**: `kaddo_create_initiative`, `kaddo_update_initiative`, `kaddo_add_initiative_candidate`, `kaddo_materialize_initiative_candidate`.
- **Initiative context** (AC-13): contexto dinámico ensamblado por Knowledge Levels (business/product knowledge, related capabilities, arquitectura relevante, System Graph si existe, candidates, WIs asociados/completados, evidencia, verificación, learning, open questions, risks). No cargar todo el proyecto.
- Patrón preview/confirm como `kaddo_mark_work_item_ready` / `kaddo_modules_discover`.

## Out of scope

- `kaddo_analyze_initiative`, `kaddo_complete_initiative` y la lógica de gap/completion (WI-020).
- Admin (WI-020).
- external_links / graph / docs (WI-021).

## Acceptance criteria

- [ ] AC-11 — CLI: Initiatives consultables y operables desde CLI.
- [ ] AC-12 — MCP: Initiatives consultables y operables desde MCP con capacidades provider-neutral.
- [ ] AC-13 — MCP Context: un agente solicita contexto relevante de una Initiative sin cargar todo el proyecto.
- [ ] AC-14 — Human Confirmation: MCP no crea Initiatives/candidates ni materializa silenciosamente (confirm=true requerido).

## Validation

- `kaddo initiative create` + `show` + `progress` devuelven estado coherente con Core.
- MCP `kaddo_create_initiative` sin `confirm` → preview; con `confirm=true` → aplica.
- `kaddo_get_initiative_context` retorna contexto acotado por Knowledge Levels, no el proyecto entero.
- Tests de: comandos CLI (snapshot/estado), tools MCP (preview vs confirm), context assembly.

## Dependencies

- WI-018 (Initiative Core). Patrón MCP confirm existente ([server.ts](packages/mcp/src/server.ts)).
