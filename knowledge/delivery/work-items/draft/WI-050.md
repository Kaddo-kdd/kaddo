# Work Item + Project Resource integration

Slice **D** de la épica [[WI-046]] (Controlled Deprecation). Depende de [[WI-047]], [[WI-048]], [[WI-049]].

## Intent

Conectar el plan con la ejecución: un plan produce WI candidates por wave; un WI materializado
referencia sus targets y, cuando aplica, sus Project Resources, y el Implementation Handoff conoce el
contexto de deprecación. El plan vive en el Core Project y abarca múltiples repos.

## Scope

- `deprecation_targets: [...]` en `WorkItemDetail` (trazabilidad WI → DEP → target), sin copiar la
  definición del target en el WI.
- **Materialización** de WI candidates desde el plan por wave.
- **Multirepo**: targets apuntan a módulos validados contra `.kaddo/modules.yml`; un plan abarca varios
  repos; no se duplica el plan en repos secundarios.
- **Resources**: targets database/external se vinculan a `resource: RES-…` y respetan sus boundaries
  (prod write/destructive → approval/runbook).
- **Implementation Handoff**: sección que incluye target / soft-state / usage-evidence / blast-radius /
  reversibility / environments / resources / rollback cuando el WI pertenece a un plan.

## Acceptance criteria

- [ ] `deprecation_targets` con trazabilidad WI → DEP → target (AC-10).
- [ ] Multirepo: targets validados contra modules.yml; un plan, varios repos (AC-03).
- [ ] Targets database/external vinculados a Project Resources respetando boundaries (AC-04).
- [ ] Handoff enriquecido con contexto de deprecación.
- [ ] Tests (materialización por wave, validación de módulo, boundary de resource).

## Entry points

- `packages/cli/src/core/work-items.ts` — `WorkItemDetail`, relaciones, `resources:[{id,role}]`.
- `packages/cli/src/core/implementation-handoff.ts` — sección "Relevant Resources".
- `.kaddo/modules.yml` + `loadMappedModules`; `packages/cli/src/core/resources.ts` (boundaries).

## Out of scope

Modelo (A), discovery (B), surfaces (C), soft/observación (E), runbooks (F), Admin (G).
