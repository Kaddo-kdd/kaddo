# WI-012 — Refinar el ciclo Legacy de Kaddo para ejecución end-to-end en sistemas reales

## Intent

### Actor

Equipo o persona que necesita comprender y modificar de forma segura un sistema legacy utilizando Kaddo y agentes de IA.

### Problema

Kaddo ya dispone de un workflow legacy funcional para descubrir y entender sistemas existentes:

```text
init --state legacy → scan → context → add agents → understand →
legacy-agent → architecture-agent → roadmap-agent →
create --from roadmap → owners suggest → guard → explain
```

Además, el lifecycle nativo de Kaddo ya soporta:

```text
Refinement → Ready → Implementation Handoff → Implementation →
Evidence → Verification → Learning
```

Sin embargo, ambos ciclos todavía no están completamente conectados.

El conocimiento generado durante el análisis legacy —riesgos, unknowns, señales del scan, System Graph y candidatos de modernización— puede perder relevancia cuando el trabajo pasa a Roadmap, Work Item, Handoff, implementación y verificación.

Antes de ejecutar el workflow sobre un sistema empresarial real, Kaddo debe convertir el análisis legacy en conocimiento operacional que acompañe el cambio de principio a fin.

## Current behavior

- Legacy workflow termina en discovery/planning (understand → roadmap → create → explain)
- Build Contract lifecycle funciona independientemente sin consumir legacy knowledge
- legacy-agent produce output genérico sin Knowledge Levels, scan signals ni System Graph
- roadmap-agent no referencia explícitamente risks/unknowns
- Implementation Handoff no inyecta contexto legacy relevante
- Guard no tiene sensibilidad legacy-aware
- No existen MCP resources para legacy artifacts
- Documentación legacy (6 archivos) predates Build Contract

## Target behavior

El ciclo legacy funciona end-to-end:

```text
Legacy Repository → Scan → Context → Understand → Legacy Analysis
(Risks, Unknowns, Modernization Candidates, Scan Signals, System Graph)
→ Architecture → Roadmap → Work Item → Refinement → Ready
→ Implementation Handoff (+ Relevant Legacy Context)
→ Implementation → Evidence → Legacy-aware Guard
→ Verification → Completed → Learning → Updated Knowledge
```

## Acceptance criteria

- [ ] AC-01: legacy-agent utiliza scan, System Graph y Knowledge relevante para producir riesgos, unknowns y candidatos de modernización estructurados
- [ ] AC-02: roadmap-agent considera explícitamente riesgos y unknowns al generar/refinar el roadmap
- [ ] AC-03: Un hallazgo legacy puede mantenerse relacionado desde el análisis hasta Roadmap y Work Item
- [ ] AC-04: El refinement de un WI legacy incorpora únicamente los riesgos y unknowns relevantes a su scope
- [ ] AC-05: Implementation Handoff incluye contexto legacy relevante para las áreas que serán modificadas
- [ ] AC-06: Existe una skill reutilizable para evaluar riesgos legacy asociados a un cambio
- [ ] AC-07: guard puede detectar cuando Evidence o cambios afectan áreas con riesgos legacy conocidos
- [ ] AC-08: Los principales artifacts de conocimiento legacy pueden consultarse mediante MCP
- [ ] AC-09: El sistema evita copiar todo el conocimiento legacy y utiliza referencias/context assembly
- [ ] AC-10: Los aprendizajes descubiertos durante implementación/verificación pueden regresar al conocimiento del proyecto
- [ ] AC-11: La documentación legacy representa el lifecycle Kaddo-native completo
- [ ] AC-12: Un proyecto legacy puede ejecutar el flujo completo desde init hasta Completed sin perder contexto legacy
- [ ] AC-13: Los workflows greenfield/brownfield y el Build Contract actual continúan funcionando sin regresiones

## Validation

Ejecutar walkthrough end-to-end en proyecto legacy de prueba (17 pasos) y comprobar que un riesgo descubierto durante análisis sea visible/referenciado a lo largo de todo el lifecycle.

## Out of scope

- Automatic legacy modernization, code migration
- Risk scoring system, legacy analytics dashboard
- AI-generated modernization execution, automatic remediation
- Organization-wide governance, advanced lifecycle metrics
- New persistence database
- Rediseño del Build Contract general
