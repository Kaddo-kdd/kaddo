## ¿Por qué Kaddo?

**Tu proyecto ya tiene conocimiento. Solo está disperso.**

En proyectos nuevos, las decisiones desaparecen rápido. En proyectos pre-IA, el
contexto nunca se preparó para los agentes. En proyectos legacy, el conocimiento suele
vivir en la cabeza de las personas.

Kaddo acerca ese conocimiento al código y ayuda a mantenerlo vivo mientras el sistema
cambia.

## Para cada etapa del proyecto

<CardGrid stagger>
  <Card title="Proyectos nuevos" icon="rocket">
    Empieza con una estructura mínima de conocimiento — roadmap, work items y contexto mínimo — sin crear sobrecarga de proceso.
  </Card>
  <Card title="Proyectos pre-IA" icon="setting">
    Escanea tu repo, organiza el contexto y haz que el proyecto sea más fácil de entender para las herramientas de IA.
  </Card>
  <Card title="Proyectos legacy" icon="open-book">
    Mapea el ownership de forma gradual y entiende las zonas de riesgo antes de cambiarlas.
  </Card>
  <Card title="Guard contra la deriva" icon="approve-check">
    Kaddo Guard cruza el `git diff` con el ownership de los artefactos y avisa cuando el conocimiento relacionado podría necesitar revisión.
  </Card>
</CardGrid>

## Cómo funciona

<CardGrid>
  <Card title="1 · Clasifica" icon="pencil">
    Declara el tipo de cambio y obtén un Nivel de Conocimiento sugerido (K0–K4).
  </Card>
  <Card title="2 · Captura" icon="document">
    Responde solo las preguntas necesarias para ese nivel — Kaddo crea un work item ligero.
  </Card>
  <Card title="3 · Observa" icon="magnifier">
    Kaddo Guard detecta cuándo un cambio de código puede afectar al conocimiento relacionado.
  </Card>
</CardGrid>
