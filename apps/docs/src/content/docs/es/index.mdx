## ¿Por qué Kaddo?

**Tu proyecto ya tiene conocimiento. Solo está disperso.**

En proyectos nuevos, las decisiones desaparecen rápido. En proyectos pre-IA, el
contexto nunca se preparó para los agentes. En proyectos legacy, el conocimiento suele
vivir en la cabeza de las personas.

Kaddo acerca ese conocimiento al código y ayuda a mantenerlo vivo mientras el sistema
cambia.

## Eficiencia de contexto mediante conocimiento estructurado

Kaddo no optimiza prompts, no comprime ventanas de contexto y no resume código automáticamente.
Optimiza lo que el agente necesita descubrir. El conocimiento Business, Product, Tech y Delivery
se convierte en una capa de contexto navegable, para que los agentes pasen menos tiempo buscando
en el repositorio y más tiempo tomando decisiones con base.

## CLI + Agentes LLM

Kaddo trabaja en dos capas.

El **CLI** se encarga de lo determinístico: inicializar el repositorio de conocimiento (con soporte bilingüe en/es),
escanear el código, crear work items y detectar posibles desviaciones entre código y
conocimiento.

El **LLM** se encarga del entendimiento: usando agentes de Kaddo para extraer
capacidades, reconstruir arquitectura, identificar riesgos y proponer un roadmap a
partir del contexto del proyecto.

> Kaddo no intenta que el CLI "entienda todo". El CLI recoge y estructura señales. Los
> agentes en el LLM convierten esas señales en entendimiento del producto.

## Cómo funciona

Kaddo no empieza creando tareas. Empieza entendiendo el estado del proyecto, y luego
construye conocimiento de forma progresiva antes de que evoluciones el código — a través de
cuatro [momentos de operación](/es/operating-moments/): **Base → Definición → Proyección →
Ejecución**.

<CardGrid>
  <Card title="1 · Inicializa y escanea" icon="pencil">
    `kaddo init` y luego `kaddo scan` — dile a Kaddo el estado del proyecto, estructura e idioma (inglés/español), y detecta stack y señales técnicas de forma determinística.
  </Card>
  <Card title="2 · Prepara el contexto" icon="list-format">
    `kaddo context` arma un context pack para el LLM y `kaddo add agents` instala los prompts de agentes.
  </Card>
  <Card title="3 · Entiende con agentes" icon="open-book">
    `kaddo understand` guía el handoff — luego usa los agentes de Kaddo en tu chat LLM para extraer capacidades, arquitectura, riesgos y un roadmap.
  </Card>
  <Card title="4 · Crea desde el roadmap" icon="rocket">
    `kaddo create --from roadmap` convierte un candidato del roadmap en un Work Item; `kaddo owners suggest` declara el ownership del código.
  </Card>
  <Card title="5 · Guard y explain" icon="approve-check">
    `kaddo guard` detecta cuándo el código puede alejarse del conocimiento; `kaddo explain` resume lo que el proyecto sabe actualmente.
  </Card>
</CardGrid>

### El flujo completo

```bash
kaddo init          # estado: new | pre-ai | legacy, tamaño de equipo, estructura, idioma (en/es)
kaddo bootstrap     # proyectos nuevos: base de conocimiento inicial (Business → Product → Tech → Delivery)
kaddo scan          # inventario técnico determinístico
kaddo context       # context pack para el handoff al LLM
kaddo add agents    # instala los agent prompt packs
kaddo understand    # plan guiado de handoff CLI → LLM
# usa tu LLM con el context pack + agentes para crear capacidades, arquitectura y roadmap
kaddo create --from roadmap
kaddo owners suggest
kaddo guard
kaddo explain
```

El CLI prepara el contexto; tu LLM lo interpreta. Kaddo nunca llama a un LLM por sí mismo.

## Escala a multirepo

Kaddo también modela un sistema repartido en muchos repositorios. Desde el repo de
arquitectura mapeas repos secundarios como módulos y mantienes su conocimiento junto al
código:

```bash
kaddo modules map        # registra un repo secundario (frontend/backend/infra…) como módulo
kaddo modules list       # lista los módulos mapeados
kaddo add standards|security|stack|git-strategy   # artefactos globales del sistema
```

<CardGrid>
  <Card title="Conocimiento por módulo" icon="document">
    `modules map` genera artefactos basados en plantillas (`module-design`, `stack`,
    `security`, `standards`) bajo `knowledge/tech/modules/<id>/`, con front matter y globs
    `code:` de ownership.
  </Card>
  <Card title="Context y explain module-aware" icon="list-format">
    `kaddo context` y `kaddo explain` muestran los módulos mapeados y su cobertura de
    artefactos — distintos de los add-ons instalados con `kaddo add`.
  </Card>
  <Card title="Guard de workspace" icon="approve-check">
    El opt-in `kaddo guard --workspace` revisa los repos locales mapeados y señala posible
    drift contra los globs `code:` — no bloqueante, sin clonar, sin APIs remotas.
  </Card>
  <Card title="Artefactos globales" icon="seti:config">
    Estándares, seguridad, stack y una estrategia de Git recomendada documentan lo
    transversal una sola vez para todo el sistema.
  </Card>
</CardGrid>

Para repos que no puedes (o no quieres) mapear, intercambia
[**Knowledge Capsules**](/es/knowledge-capsules/) — `kaddo capsule export` comparte un resumen
mínimo de un sistema; `kaddo capsule add` lo importa como *External Knowledge* en el context
pack. Sin mapeo multirepo, sin acceso al código.

Mira la guía de [Módulos multirepo](/es/modules/multirepo/) y la
[Guía visual](/es/visual-guide/) para el mapa completo del sistema.

Kaddo es una implementación práctica de [**Knowledge Driven Development**](/es/knowledge-driven-development/)
para el desarrollo de software asistido por IA — aplica los principios de KDD; no afirma
haberlos inventado.
