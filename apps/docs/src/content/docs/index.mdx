## Why Kaddo

Projects degrade because knowledge is scattered across meetings, chats, tickets,
and outdated documents. With AI, this gets worse: agents build on assumptions when
they lack context. Kaddo keeps the minimum necessary context alive next to the code.

<CardGrid stagger>
  <Card title="Knowledge first" icon="open-book">
    Work Items carry the minimum context for their Knowledge Level (K0–K4).
  </Card>
  <Card title="Ownership in front matter" icon="document">
    Artifacts declare the code they own. No central mapping file.
  </Card>
  <Card title="Guard, not bureaucracy" icon="approve-check">
    Guard reads `git diff` and shows a non-blocking FYI when code drifts from its knowledge.
  </Card>
  <Card title="Built for agents" icon="rocket">
    `kaddo explain --for agent` emits structured JSON so AI tools start with real context.
  </Card>
</CardGrid>

## How it works

In three steps Kaddo turns scattered context into observable knowledge.

<CardGrid>
  <Card title="1 · Capture" icon="pencil">
    `kaddo create` asks only the questions that match the size of the change.
  </Card>
  <Card title="2 · Own" icon="setting">
    Each artifact declares the `code:` globs it owns — a runtime Knowledge Graph.
  </Card>
  <Card title="3 · Observe" icon="magnifier">
    `kaddo guard` intersects the diff with that graph and surfaces drift.
  </Card>
</CardGrid>
