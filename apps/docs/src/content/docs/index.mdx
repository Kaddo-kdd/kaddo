## Why Kaddo?

**Your project already has knowledge. It is just scattered.**

In new projects, decisions disappear fast. In pre-AI projects, context was never
prepared for agents. In legacy projects, knowledge often lives in people's heads.

Kaddo brings that knowledge closer to the code and helps keep it alive as the system
changes.

## For every project stage

<CardGrid stagger>
  <Card title="New projects" icon="rocket">
    Start with a minimal knowledge structure — roadmap, work items and minimum context — without creating process overhead.
  </Card>
  <Card title="Pre-AI projects" icon="setting">
    Scan your repo, organize context and make the project easier for AI tools to understand.
  </Card>
  <Card title="Legacy projects" icon="open-book">
    Map ownership gradually and understand risky areas before changing them.
  </Card>
  <Card title="Guard against drift" icon="approve-check">
    Kaddo Guard checks `git diff` against artifact ownership and warns when related knowledge may need review.
  </Card>
</CardGrid>

## How it works

<CardGrid>
  <Card title="1 · Classify" icon="pencil">
    Declare the type of change and get a suggested Knowledge Level (K0–K4).
  </Card>
  <Card title="2 · Capture" icon="document">
    Answer only the questions needed for that level — Kaddo creates a lightweight work item.
  </Card>
  <Card title="3 · Observe" icon="magnifier">
    Kaddo Guard detects when code changes may affect related knowledge.
  </Card>
</CardGrid>
