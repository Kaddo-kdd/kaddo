## Why Kaddo?

**Your code changes. Your knowledge often does not.**

Architecture decisions, product context, contracts, and implementation details usually
live in chats, tickets, meetings, or someone's head. Kaddo keeps that knowledge close
to your code and helps detect when it may fall behind.

<CardGrid stagger>
  <Card title="Minimum context, not more docs" icon="open-book">
    Kaddo uses Knowledge Levels K0–K4 to ask only what each change needs.
  </Card>
  <Card title="Work items close to code" icon="document">
    Create lightweight, traceable artifacts for features, hotfixes, spikes, and migrations.
  </Card>
  <Card title="Guard against knowledge drift" icon="approve-check">
    Kaddo Guard checks `git diff` against artifact ownership and warns when related knowledge may need review.
  </Card>
  <Card title="Built for humans and agents" icon="rocket">
    Structured knowledge helps developers, teams, and AI tools work with better context.
  </Card>
</CardGrid>

## How it works

<CardGrid>
  <Card title="1 · Classify" icon="pencil">
    Declare the type of change and get a suggested Knowledge Level.
  </Card>
  <Card title="2 · Capture" icon="setting">
    Answer only the questions needed for that level — Kaddo creates a lightweight work item.
  </Card>
  <Card title="3 · Observe" icon="magnifier">
    Kaddo Guard detects when code changes may affect related knowledge.
  </Card>
</CardGrid>
